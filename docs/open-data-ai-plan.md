# 剪贴板定位、数据自主与 AI 隐私设计

状态：2026-10-26 先完成的产品设计与路线参考。用户随后确认同时开发，首版已实现隐私、标签、规则、域名筛选及只读 AI 接入；**当前实现和限制以 [使用说明](privacy-ai.md)、[产品范围](product.md) 和 [验证记录](verification.md) 为准**。下文的布局细节与后续扩展不全部等于现有功能。首版连接仅当前进程有效；不支持历史扫描暂停续扫、规则测试面板、可选子域规则或分页游标。可点击的 [布局设计稿](design/open-data-privacy.html) 仍只使用固定样例，不读写数据库或剪贴板。

## 1. 产品定位与分享顺序

对外首先介绍：**星笺 Starclip · 本地剪贴板管理工具**。

第一句话说清用途：「找回复制过的文字、图片、链接和代码，搜索、收藏，再次使用。」接下来讲数据自主：本地保存、JSON 导入导出、自选数据目录与迁移。星空主题、卡片制作和星伴作为特色，不占据产品类别的位置。

当前可宣传数据导入导出，但不写「任意大小、完整环境跨系统无损搬家」。普通 JSON 包含片段、分组和图片，不含所有偏好及成长；有单份大小 / 数量上限，完整环境迁移还有平台边界，见 [产品范围](product.md)。

未来 AI 能力完成验收后，才增加「为 AI 开放你选择的资料」这一层：MCP 连接、CLI 自动化、Skill 使用指南。不能用开发用项目知识库或月光笺的渲染 CLI 代替这些能力。

| 核实项目 | 设计前的实现快照 | 本次设计 |
| --- | --- | --- |
| 剪贴板 | 文字 / 图片、搜索、类型、星标、分组 | 保持工作台中心地位 |
| 数据自主 | JSON 导入导出、目录迁移、恢复点 | 元数据随备份保留；完整备份与 AI 输出分开 |
| 记录标签 / 隐私字段 | 尚无 | 普通标签与独立隐私状态 |
| 自动链接分类 | 仅识别 link 类型和显示 hostname | 解析 URL、来源筛选和自定义域名规则 |
| 自动敏感检测 | 尚无 | 本地检测、解释命中、人工复核 |
| MCP / 数据 CLI / 对外 Skill | 尚无 | 统一只读权限层后接入，默认关闭 |

核实入口：`src/types.ts`、`src/App.vue`、`src-tauri/src/{main,store,desktop,storage,handwriting}.rs`。

## 2. 界面布局

### 工作台

- **左栏：** 全部记录、星标、永久保留和现有类型；「链接」展开后显示来源：微信公众号、LINUX DO、X、哔哩哔哩、其他域名。只展示命中的来源，其余收在「更多来源」中，避免每个网站都占一个顶层导航。
- **独立筛选：** 隐私记录、待复核；普通标签单独折叠，原有分组保留。隐私不是一种互斥内容类型，一条代码或链接也可以是隐私。
- **中间列表：** 搜索、来源、标签与隐私筛选按 AND 组合；已选条件用可移除筛选项显示。记录卡片显示标题、类型、来源域名，最多两个普通标签及「+N」，隐私记录正文默认折叠，显示锁标识和「隐私 · 不向 AI 提供」。
- **右侧详情：** 正文 / 图片、复制等现有操作；下方依次为来源、普通标签、隐私与 AI 状态。隐私区展示「手动标记 / 规则命中 / 待检测」及规则名称，不把秘密匹配片段放进提示。设置隐私与永久保留是两件事，不互相替代。
- **窄窗口：** 详情改为抽屉；来源用筛选按钮弹层；主工作流不被长列表和规则编辑器挤占。弹层支持 Escape、外部关闭、焦点恢复。

完整原文仍由用户在本地按需展开。折叠是防止旁观，不是加密；关闭详情、离开隐私筛选后重新折叠。用户主动复制隐私内容应明确反馈复制结果，应用不承诺清除其它软件保存的剪贴内容。

### 偏好设置

沿用现有分区，随着功能实现将「记录与隐私」扩展为「规则与隐私」，新增「AI 与自动化」。内容变多时设置采用左侧导航，窄屏使用分类选择器，避免七个横向标签拥挤；保留现有草稿、滚动和忙碌保护约定。

| 分区 | 布局与操作 |
| --- | --- |
| 规则与隐私 | 顶部采集 / 保留；中部「敏感内容」「链接来源」「自动标签」；底部规则列表、停用、原创样例测试、历史应用预览 |
| AI 与自动化 | 默认关闭的总开关；连接列表与撤销；每连接允许分组 / 标签、字段与额度；只读工具清单；MCP 配置 / CLI / Skill 接入说明；本地调用记录 |
| 数据管理 | 当前路径与占用；「导出完整备份」「导入备份」；恢复 / 迁移独立区域；说明备份是否包含隐私，不把 AI 输出叫完整备份 |
| 帮助 → 分享星笺 | 剪贴板总览为默认图，数据自主为第二图；副功能图仍注明剪贴板产品；文案、复制图、保存图保持就近回执 |

隐私保护、连接撤销和 AI 关闭属于独立即时操作；普通规则草稿需保存才生效，历史批处理是独立确认。不能借保存这些操作提交外观草稿或触发历史清理。即时操作失败要恢复确认过的状态并显示错误。

## 3. 隐私规则：标签可见，权限独立

不把字符串「隐私」当作唯一安全开关。拟在存储层区分：人工隐私标记、规则保护原因、扫描状态 / 规则版本、普通标签、来源域名。界面以一个明确的隐私标识呈现，内部有任一保护原因就不向 AI 提供。

建议 AI 可见条件为：连接已启用且有效 **AND** 记录在用户授权范围内 **AND** 已完成当前规则扫描 **AND** 没有隐私 / 待复核原因 **AND** 请求字段获准。域名分类、普通标签与分组不会自动授予权限。

优先级：**手动隐私或敏感命中 > 连接允许范围 > 普通分类**。用户明确标隐私后，重新复制、导入合并、关闭规则、移除普通标签都不能自动解除。新规则只增加保护；解除保护单独查看原因并由用户在本地操作，仍命中有效规则时不能仅删除外观标签绕过。

用户授权范围初始为空。可按分组或标签筛选后批量确认本次允许的记录，授权绑定明确的记录集合，不是随分类自动变化的集合；之后新增记录、自动加标签、导入或移入分组都不会自动获得授权。既有记录不能因为升级就向 AI 开放；全库扫描完成前连接保持不可用。对新内容、修改和导入在提交数据前执行扫描；扫描失败或暂未扫描默认不向 AI 提供。

### 默认敏感规则

| 规则 | 检测方式与界面解释 | 建议默认行为 |
| --- | --- | --- |
| 助记词 | 支持词表内的词序列、合法词数与校验和；分别显示「符合 BIP-39 格式」或「疑似助记词」 | 标记隐私并折叠，不向 AI 提供 |
| 私钥 | PEM 私钥块等高置信结构；其它格式按独立、可测试规则增加 | 标记隐私 |
| API 凭据 | 明确的密钥前缀 / 授权头 / 密码字段结合长度与结构；不把任何长字符串都判成密钥 | 命中或疑似均隔离，允许本地复核 |
| 敏感链接 | URL 用户名密码、凭据相关参数（如 access_token / password / secret） | 保留本机来源分类，但整条不向 AI 提供 |
| 用户规则 | 关键词、域名、文本结构条件与「加标签 / 标记隐私」动作 | 本地测试后启用，不能用规则自动取消隐私 |

助记词不能只按「12 个英文词」判定。BIP-39 定义 12 / 15 / 18 / 21 / 24 词和校验和；符合格式不代表钱包有效、不说明是否持有资产，也不意味着其它钱包格式能被识别。首版建议明确列出支持的词表（优先英语、简体中文），规范化 Unicode 与分隔符；词表与校验实现需单独核对许可及测试。依据：[BIP-39 原始规范](https://github.com/bitcoin/bips/blob/master/bip-0039.mediawiki)。

识别在本机完成，不将内容交给云模型分类。无 OCR 时无法识别图片中的秘密，首版 AI 图片读取默认不提供；以后单独增加用户明确授权与相应检测。自动识别会漏报和误报，界面不能显示「检测通过＝绝对安全」。可追加「不保存此类内容」动作，但这会丢弃采集内容，必须由用户主动选择，不能悄悄替代现有长期保留。

历史重扫先显示范围 / 预计新增保护数，不预览完整秘密，提交后可暂停续扫。规则停用不撤回已有保护。规则测试默认使用原创样例，用户贴入的测试文本仅在本地临时处理，不进入历史、日志、成长记录或分享图。

## 4. 链接来源与域名规则

用标准 URL 解析得到 hostname，仅处理 HTTP(S)，大小写 / IDNA / 尾部点按一致规则规范化；原文不被改写。按明确的主机名和子域边界匹配，不用全文 contains，也不把可视名称当身份。

| 来源 | 首批规则 | 说明 |
| --- | --- | --- |
| 微信公众号 | 精确 `mp.weixin.qq.com` | 来源标签称「微信公众号」；仅域名命中不证明链接必定是文章 |
| LINUX DO | `linux.do`；可选包括其子域 | 不把包含这串文字的其它网站计入 |
| X | `x.com`、`twitter.com` 的明确主域 / 子域规则 | `t.co` 另标「X 短链 · 目标未解析」，不推断目标平台 |
| 哔哩哔哩 | `bilibili.com` 及其子域，精确 `b23.tv` | `b23.tv` 标为短链，不承诺具体视频类型 |
| 其他网站 | 完整规范化 hostname | 用户可将当前域名保存为来源规则，默认精确匹配 |

这些是内置匹配规则的设计清单，不表示已经联网验证每个链接或解析短链。用户可编辑、停用和添加；界面把「包括子域名」作为单独选项，不能通过模糊输入无意扩大范围。

必须拒绝错误归类：`x.com.evil.example`、`evil.example/?next=https://x.com`、`https://x.com@evil.example`。`https://user:pass@x.com` 虽有真实 x.com 主机，仍被敏感规则阻止 AI 获取整条。

一条文字含多个 URL 时可具有多个来源，筛选命中任一提取链接；它仍保留原本的文字类型。提取数量、输入长度设上限，超限标注处理不完整而不伪装全量识别。保留每个匹配的规则 ID / 版本与 hostname，普通标签去重；来源规则不覆盖用户分组。

初版不抓网页正文、标题或 favicon，不自动跳转短链，不发送域名到远端分类服务；来源名称来自内置表。搜索索引 / 预览中的敏感 URL 参数不额外复制到日志。未来网页解析须另行设计网络授权、隐私与 SSRF 边界。

## 5. MCP、CLI、Skill 共用一个后端权限入口

MCP 是协议、CLI 是调用方式、Skill 是使用说明。三者不各自实现一套数据授权。建议先做供外部调用的 Rust 只读访问层，再由 CLI 和本地 stdio MCP 桥接；桌面主应用持有策略与连接授权，桥接不直接打开 SQLite 或导出备份文件。具体 IPC 实现进入开发时再选，不预先新增框架或远程服务。

| 首版建议开放 | 输出与限制 |
| --- | --- |
| search | 授权范围内的有限条结果；筛选先于搜索、分页和计数；摘要长度有上限 |
| get | 再次按当前策略校验 ID，仅返回获准字段；不存在与无权限统一响应 |
| list_sources / list_tags | 只统计可见资料，不泄漏私密记录的域名、标签和分组名 |
| status | 连接是否可用、工具能力与限制，不含数据目录、全库数量或秘密 |

首版不开放写入、删除、改隐私状态、任意 SQL / 路径、实时系统剪贴板、完整备份 / 恢复、更新安装或执行代码。暂不开放图片、资源订阅、批量导出；以后加入时必须沿用同一过滤，不通过新增 tool 绕过。

授权在本地界面显式创建，可按分组 / 标签 / 类型筛选并预览本次记录集合，确认获准字段、单次结果上限与有效期；用户要分享后来增加的内容时再次确认。来源分类和自动标签不进入授权计算。CLI 和 MCP 都使用可撤销的连接凭证，不能相信请求里自报的 `human=true` 或 `trusted=true`。复制接入配置仅按用户操作进行，默认不写入其它软件设置。撤销 / 关总开关立即影响后续读取。

每次响应生成前重新检查策略版本；读取过程中发生保护变更则重做或拒绝，不能返回陈旧缓存。不要持久缓存已输出的正文，分页游标不能跨策略修订继续读取。已经交给外部 AI 的内容不能承诺撤回。

本地调用记录只记连接显示名、动作、时间、返回数量与结果，不记录搜索词、原文、标题、完整 URL 或密钥；默认保留窗口与清除入口由实现时明确。所有返回内容均标识为用户资料而非可执行指令，剪贴正文中的提示不能改变工具权限。

Skill 说明工具用法、只读限制、错误处理和隐私约定；不能靠一句「请不要读取隐私标签」替代后端过滤。MCP 的权限与本地服务信任边界参考 [官方安全指南](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices)，本设计中的授权范围和只读工具是星笺自身的产品选择。

**保护范围必须说清：**「隐私 · 不向 AI 提供」指星笺的官方接口；数据库、备份仍是本机明文。获得同账户文件权限、屏幕读取或桌面操作权限的外部程序可能绕开接口。不能宣传为系统级 AI 隔离；磁盘加密 / 密钥保管属于另一个功能，未在本轮实现。用户将允许的内容交给远端 AI 后，其处理方式由该 AI 服务决定，不能继续宣称“全程不出本机”。

## 6. 数据迁移与一致性

- 复用现有结构升级与升级前快照路径，为隐私、标签、来源和规则版本增加显式结构版本；不能直接改旧表后跳过备份与未来版本拒绝。
- 新备份格式包含这些元数据及规则配置；旧 v1 / v2 导入仍可用，缺少隐私信息的内容先扫描。导出完整备份保留全部隐私数据并在本地入口明确提示，不能为“保护 AI”悄悄漏数据。
- 所有导入内容都按本机当前规则重新扫描，不信任备份自报的扫描状态 / 规则版本。导入的规则配置仅成为停用草稿，需本地预览和确认才能应用；不能自动覆盖 / 停用本机隐私规则、解除保护或扩大连接授权。
- 重复内容合并保留现有手动隐私并合并保护原因；导入文件只能增加保护，不能用 `private=false` 解锁当前记录。来源可按新规则重算，用户标签保留。
- 采集、手动新增、代码保存、内容修改、图片元数据与导入共用规则入口；规则和写入同事务，不能先广播未检测内容再补标签。
- 完整恢复后先检查当前规则状态，重新授权连接；连接密钥与启用状态不应作为可跨机器直接生效的普通备份设置。
- 前端普通用户视图可以显示本机全部记录；AI 不复用 `get_state`、清理预览、备份或图片原始命令。当前 `get_state` 把正文交给主窗、搜索和计数在前端进行，必须新建受控查询入口。

## 7. 实施顺序与验收门槛

| 阶段 | 交付 | 完成门槛 |
| --- | --- | --- |
| 本轮 | 分享定位、数据自主文案、布局原型与本设计 | 原图视觉检查、压缩、现有复制 / 保存检查；新能力明确标规划 |
| 1 · 数据基础 | 隐私字段、普通标签、来源、规则配置、结构升级及备份保真 | 人工隐私不被重复捕获 / 合并 / 改规则解除；导入导出往返保留 |
| 2 · 自动整理 | 助记词 / 秘密规则、域名识别、来源筛选、历史扫描和复核 UI | 正反夹具覆盖；无外发；超限和扫描失败不向 AI 开放 |
| 3 · AI 只读 | 统一受控查询、连接 / 撤销、CLI、MCP、用户 Skill | 越权测试通过后再开放连接和宣传；macOS / Windows 分别验收 |

安全验收至少包含：搜索摘要、猜 ID、分页、总数、域名 / 标签 / 分组枚举、图片与缩略图、报错、日志、事件、批量读取的保护一致性；标私密与读取并发；扫描失败；撤销后的旧连接；旧备份 / 重复导入不降级。采用原创固定数据和公开测试向量，不读取真实剪贴板、个人数据库、真实助记词或凭据。

交互验收包含：来源多选与 AND 筛选说明、清空条件、隐私折叠 / 展开、规则命中解释、待复核状态、错误恢复、空状态、键盘焦点、窄窗口布局。平台编译不能替代完整原生验收。
